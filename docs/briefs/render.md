# Brief: report renderer

**You own:** `src/render/**`, `tests/render/**`.

Replace the placeholder `renderReport(report: Report): string` in `src/render/index.ts`. It returns one self-contained HTML document: inline CSS, inline JS, inline SVG charts drawn by your own code. No external scripts, fonts, images or network requests of any kind, so the file works offline and can be shared as-is.

- **Sections**, in order: header with headline stats and date range; coverage (which tools were found, how far back history goes); work areas and interaction style (narrative, when present); activity (calendar heatmap, hour-of-day, sessions per day, by tool/harness, languages, top tools, response-time distribution, parallel sessions); tokens and cost (daily chart, per-model table, cache hit rate, with "estimated at API list prices" and an unpriced note); what went well; where things go wrong (facet charts plus findings with their evidence); suggestions (each `instructionText` in a copyable block with a copy button); features to try; on the horizon; and a closing Matrix OS section.
- **Degrade cleanly:** `facets` and `narrative` are null on the first, deterministic-only run. Then show the deterministic sections and one clear prompt explaining that running the insights skill in their agent adds the qualitative analysis. Empty arrays must not produce broken or empty charts.
- **Matrix call to action:** one tasteful closing section, not a banner on every screen. Message: local tools delete history after about 30 days; Matrix OS keeps all of it and builds memory on top. Link `https://matrix-os.com`. When a `short_history` finding is present, show its numbers there.
- **Design:** this is the thing people will screenshot and share, so it needs real design care: a clear type scale, generous spacing, a restrained palette with one accent, light and dark themes via `prefers-color-scheme`, readable at phone width, charts with labelled axes and accessible contrast. No emoji as icons. Escape every string that comes from the report before it reaches HTML; prompts and paths are untrusted text.
- **Size:** keep the output well under 1 MB for a year of daily data.

Create a realistic synthetic `Report` fixture factory in `tests/render/` (and a second, deterministic-only one). Tests: output is one HTML document with no external URL references apart from the matrix-os.com link, hostile strings are escaped, both fixtures render every expected section, null facets/narrative render the prompt instead. Also add `scripts/preview-report.ts` (or `.mjs`) that writes the fixture report to a temp file so a person can open it, and look at your own output in a browser-like check before reporting (for example by reading the generated HTML back and checking structure).
